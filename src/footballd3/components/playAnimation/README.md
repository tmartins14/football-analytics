# playAnimation

Animates the ball's path through the event sequence in a configurable time window
around any anchor event, on the StatsBomb pitch. Designed as a general-purpose
play animation engine — the goal-build-up use case (the most common consumer) is
produced by the `extract_goal_animation` Python wrapper. The user can play, pause,
and scrub through the build-up at configurable speed.

## Honest limitations — read before using

**(a) This is NOT 22-player tracking.** StatsBomb open data contains no continuous
positional tracking. This component animates the **ball** and the **players who touched
it** (from event data), using only their on-ball moments. Off-ball player movement and
positioning are entirely absent — those players' locations between events are unknown and
are not shown.

**(b) Ball paths are straight event-to-event line segments**, not real ball trajectories
or arcs. StatsBomb records where the ball was at the start and end of each event; what
happened in between (curve, bounce, flight) is unknown. Lines connect the known points.

**(c) `window_seconds` is a configurable design choice, not a canonical value.** The
default (10 seconds) was selected to capture a typical attacking build-up without
including too much unrelated build-out play. Adjust it to suit your analysis — longer
windows show more context; shorter windows focus on the final touch sequence.

**(d) Players appear only at their events.** Each actor marker appears at the moment they
touch the ball, at the location of that touch. Players do not move between events; their
between-event positions are unknown.

## Component purpose

`createPlayAnimation(pitch, data, config)` — composing on `pitch.js`. Receives an
existing pitch object and draws the animation into `pitch.g` using `pitch.px()` for
coordinate conversion. Does not create or re-render the pitch.

The component owns its playback state (playhead, playing/paused, current segment) inside
a closure. External control is via the returned `controls` handle. A `onTimeUpdate`
callback keeps external scrubber UI in sync without the component needing DOM references.

Events from both teams are included in the window. The `team` field on each frame
allows the caller to differentiate sides if needed (currently unused by the renderer).

### Field definitions

| Field | Type | Description |
|---|---|---|
| `t_seconds` | float | **Clip-relative** seconds (0.0 at first frame, increasing). Not absolute match time. |
| `window.t_span_seconds` | float | Convenience: last frame's `t_seconds`. Use as clip duration base. |
| `ball_x`, `ball_y` | float | Event origin in StatsBomb 120×80 coords (native; `pitch.px()` converts) |
| `ball_end_x`, `ball_end_y` | float\|null | End location for Pass/Carry/Shot; null for point events (Pressure, Duel, etc.) |
| `team` | string | Team name for this event (both teams included in window) |
| `actor` | string | Resolved `display_name` (nickname coalesce, Python-side) |
| `outcome` | string\|null | Pass failure reason or null (null = completed pass, or non-pass event) |
| `context.goal` | object\|absent | Populated only by `extract_goal_animation`; absent for general clips |

`actor_x`/`actor_y` are not emitted — in StatsBomb events the actor is always at the
event origin, so they are always equal to `ball_x`/`ball_y`.

## Config options

```js
createPlayAnimation(pitch, data, {
  playbackSpeed:    2.0,     // real-time multiplier; 2.0 = 10s real plays in 5s
  ballRadius:       5,       // ball circle radius in pixels
  ballColor:        "#FAF7F0",
  ballStroke:       "#171717",
  actorColor:       "#9F1239",
  trailOpacity:     0.15,    // reserved for future use; trails currently render at full opacity
  actorFadeOpacity: 0.12,    // opacity of previous actor halos
  onTimeUpdate:     null,    // callback(clipSeconds) fired each animation tick
})
```

### `onTimeUpdate` callback

The component does not create DOM controls. Pass a callback to receive clip time updates
and sync an external scrubber:

```js
const scrubber = document.getElementById("my-scrubber");
const anim = createPlayAnimation(pitch, clipData, {
  onTimeUpdate: (clipSeconds) => {
    scrubber.value = clipSeconds;
  },
});
```

## Return shape

```js
{
  g:        d3.Selection,          // top-level <g> appended to pitch.g
  controls: {
    play:   function(),            // start playback from current position
    pause:  function(),            // freeze at current position
    seek:   function(clipSeconds), // jump to a clip-relative time and re-render
  },
  update: function({ frames?, playbackSpeed? }) // replace data or change speed
}
```

## Usage example

```js
import { createPitch }         from "./components/pitch/pitch.js";
import { createPlayAnimation } from "./components/playAnimation/playAnimation.js";

fetch("sample_data/goal_animation_3943043.json")
  .then(r => r.json())
  .then(data => {
    const clipData = data.goals[0];  // pick one clip from goals[]

    const pitch = createPitch(d3.select("#my-svg"), {
      mode:      "full",
      pxPerYard: 7,
      theme:     "whiteboard",
    });

    const clipDuration = clipData.window.t_span_seconds + 1.0; // +1s for final frame
    const scrubber = document.getElementById("scrubber");
    scrubber.max = clipDuration.toFixed(2);

    const anim = createPlayAnimation(pitch, clipData, {
      playbackSpeed: 2.0,
      onTimeUpdate:  (t) => { scrubber.value = t; },
    });

    document.getElementById("play-btn").onclick  = () => anim.controls.play();
    document.getElementById("pause-btn").onclick = () => anim.controls.pause();
    scrubber.oninput = () => anim.controls.seek(parseFloat(scrubber.value));
  });
```

## Layer ordering (within pitch.g)

1. `<g class="ga-trails">` — trail lines of all completed ball segments
2. `<g class="ga-actors">` — previous actor halos at low opacity (accumulate)
3. `<g class="ga-actor-current">` — current actor ring + name label at full opacity
4. `<g class="ga-ball">` — ball circle (always on top)

## Event type handling

Trail lines (completed segments) are colored and weighted by event type, matching
the pass/carry map convention:

| Type | Ball moves? | Trail color | Trail weight |
|---|---|---|---|
| Pass | Yes | `#9F1239` red | 1.5px |
| Carry | Yes | `#1E3A5F` navy | 2.5px |
| Shot | Yes | `#525252` gray | 1.5px |
| Pressure, Duel, Interception, Ball Recovery | No | — (no trail) | — |

Point events (no `ball_end_x`) draw no trail line. The ball pauses at its current
position while the actor ring appears with a dashed stroke.

Ball Receipt* is excluded from the contract (clusters on top of Pass end-points with no
independent spatial information).
